# What belongs in ~/.venv-stayturgid-firerpa, the venv behind the live
# com.stayturgid.firerpa-mcp and com.stayturgid.firerpa-health launchd services.
# ansible/roles/control_node/tasks/firerpa_venv.yml converges the venv from this file.
#
# Nothing is pinned here; site policy is to track the latest release. The one
# exception is lamda's version, and it isn't set here: firerpa_venv.yml adds
# `lamda==<release>` for the FIRERPA release that this converge resolved, which
# keeps the Mac client in lockstep with the server the firerpa role deploys.
# lamda comes from PyPI (upstream publishes a correctly named lamda-<v>.tar.gz
# sdist there). Its dependencies (grpcio, grpcio-tools, protobuf, ...) come with
# it, bounded only by lamda's own caps (grpcio/grpcio-tools <=1.82.0).
lamda
# control/bin/firerpa_mcp.py and control/lib/firerpa_consent.py (mcp 2.x MCPServer API)
mcp
